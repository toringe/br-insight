# AGENTS.md

Static site for [Blade Runner Insight](https://www.br-insight.com) (br-insight.com). Plain HTML/CSS/JS output produced by a small Python build pipeline (`src/br_insight/`, managed with [uv](https://docs.astral.sh/uv/), Python 3.14). No web framework and no Node toolchain.

## Layout

- `src/br_insight/` — the build pipeline package (`br-insight` console script: `build` / `serve` / `check`). Render templates live in `templates/`.
- `templates/` + `_data/` — Jinja2 page sources (`base.html`, `home.html`, `library.html`, `article.html`, `about.html`, topic pages, shared fragments in `partials/`) and site data (`_data/site.yaml`, `_data/taxonomy.yaml`, `_data/topics.yaml`).
- `assets/js/` — client JS as ES modules: `main.js` imports feature modules from `modules/` (progress, toc, endnav, focus, memory, shortcuts, search, filter, archive, revisions, fx, rain). `search-index.json` is generated by the build (`src/br_insight/search.py`) and fetched lazily by the search overlay.
- `library/<article-slug>/` — one directory per article:
  - `article.md` — Markdown source with YAML front matter (`title`, `author`, `cover`, `date`, `taxonomy.category`, `summary.enabled/size`). **The article workflow is: edit `article.md`, then rebuild — never hand-edit the rendered HTML.**
  - `index.html` — rendered output of `article.md` (what serves); regenerated by the build.
  - `cover.jpg|png` plus generated responsive variants (`cover-{W}`, `cover-crop-{W}` in WebP + JPEG).
- Built outputs land **in place** at the repo root (`index.html`, `about.html`, `library/*/index.html`, `topics/…`, `feed.xml`, `sitemap.xml`, `llms.txt`, `404.html` + its byte-identical `error.html` twin). Static tree = deployable root (S3+CloudFront-style hosts; map host 404 config to `error.html`).

## Commands

```
uv sync                            # set up the environment
uv run br-insight build            # render Markdown articles → static tree (repo root)
uv run br-insight serve            # serve the built site at http://localhost:8000
uv run br-insight check            # audit budgets + internal link integrity
uv run pytest -q                   # test suite
uv run python scripts/minify_css.py    # REQUIRED after editing any assets/css/*.css
```

- Pages load the **minified** CSS (`main.min.css`). After editing a source `.css`, regenerate `.min.css` via `scripts/minify_css.py`.
- `scripts/normalize_frontmatter.py` normalizes article front matter in place.
- The built tree must stay pristine w.r.t. the test suite: run `uv run pytest -q` after builds/edits; keep `404.html` and `error.html` identical.
- Article URLs are stable (`/library/<slug>/`) — renaming slugs changes public URLs; don't do it casually.
- Atmosphere FX (rain, scanlines, grain, neon flicker, welcome flicker) are gated by `data-fx-*` attributes baked on `<html>` at build time and synced at runtime by `modules/fx.js` (payload in `window.__FX__`); CSS honors `prefers-reduced-motion` — new decorative animation must hook the same flags, not run unconditionally.
- The about page's mailto link relies on **Cloudflare Email Address Obfuscation** (Scrape Shield) for scraping protection; if the site ever moves off Cloudflare, switch to client-side email assembly.
- Cache busting: `asset_ver` hashes only `assets/js/main.js` and `assets/css/main.min.css` — files under `assets/js/modules/` have no version param, so after changing a module assume cached copies in production.
- Some JS-contract tests (`tests/test_archive_js.py`, `tests/test_main_random.py`) run under Node and are skipped automatically when Node isn't installed.

## Conventions

- Commit messages follow Conventional Commits (`feat:`, `fix:`, `chore:`, …). Adding a new essay to `library/index.html` listings is a "re-indexed" chore commit.
